## Gamer Club — сайт компьютерного клуба (React + Vite + TypeScript + Express + MySQL)

**Status:** Maintained / polishing
**Next:** deploy + screenshots (frontend + API)

**Кратко (30 сек):** веб-приложение компьютерного клуба: регистрация/вход, карточки ПК и бронирование по времени с блокировкой слота. Есть профиль пользователя (редактирование контактных данных) и черновая админ-панель (список ПК + поиск). Реализовано быстро под дедлайн; сейчас идёт доводка до продакшен-стандарта.

**Origin & статус.** Проект стартовал как дипломная/заказная работа с жёсткими сроками. В коде есть технический долг (см. «Известные ограничения» и «Roadmap»). База заведена без изображений для карточек (только alt-описания) — будет исправлено миграциями.

### Highlights
- **Auth:** JWT (Bearer/httpOnly — зависит от конфигурации)
- **Booking:** логика слотов бронирования + базовая валидация
- **UI:** React + Vite + TypeScript, Tailwind + HeroUI
- **Backend:** Express REST API + MySQL (схема/сиды в `db/gamer_club.sql`)
- **Admin (draft):** список ПК + поиск (CRUD в roadmap)

## Стек
- **Frontend:** React 18, Vite, TypeScript, JSX/TSX
- **UI:** Tailwind CSS + HeroUI
- **Состояние:** локальный state (useState/useEffect), контролируемые формы
- **Backend:** Node.js, Express, CORS, body-parser, dotenv, jsonwebtoken
- **База Данных:** MySQL (mysql2). Схема в *gamer_club.sql*
- **Авторизация:** JWT (Bearer / httpOnly cookie)
- **Сборка/Dev:** Vite Dev Server (прокси /api → http://localhost:3000)

> Конфигурация Vite с прокси на бэкенд: vite.config.ts (/api → http://localhost:3000).
Tailwind с HeroUI подключён через tailwind.config.js (сканирование ./src/**/*.{ts,tsx}).

## Фичи (то, что есть сейчас)
- **Регистрация/авторизация;** роли: user, admin
- **Каталог ПК:** список карточек, бронирование по карточке с блокировкой ПК на заданный интервал.
- **Профиль пользователя:** изменение имени, телефона, email
- **Админ панель (черновик)** страница **списка ПК** + поиск (редактирование/удаление/добавление — в планах), страницы бронирований, пользователей, аналитики (функционал - в планах)

> На карточках сейчас нет изображений — только alt-тексты. В БД будет добавлено хранение ссылок на изображения (см. Roadmap).

## Переменные окружения

```bash

DB_PORT=3306
DB_NAME=game_club
DB_USER=...
DB_PASSWORD=...

# JWT secret (для подписи токенов)
JWT_SECRET=SECRET

```

## Безопасность
- **Пароли:** хранение только в виде хэш-сумм (bcrypt, >= 12 rounds).
- **JWT:** выбрать одну стратегию; для JWT — httpOnly cookie + refresh-токены и ротация.
- **Валидация на сервере:** строгая валидация всех параметров бронирования (ПК, дата/время, пересечения).
- **Роли:** роли user/admin с проверкой на уровне middleware.
- **Секреты:** все ключи/доступы — только через .env без жёстко прошитых ключей.
- **Rate limits:** на /api/auth/*, /api/bookings/*.

## Доступность (А11у)
- Полная **клавиатурная навигация** (Tab/Enter), видимые фокусы
- **Alt-тексты** для изображений ПК; для иконок - *aria-label*
- Контраст, размеры кликабельных элементов ≥ 44×44px

## Метрики (цели для мобильных)
- Lighthouse: **90–100**
- Web Vitals: **LCP < 2.0 s**, **CLS ~ 0.01**
- Bundle: **≤ 350 KB** (с учётом Tailwind/HeroUI)

## Известные ограничения / баги
- **Бронирование не освобождает ПК по истечении времени.** Нужен механизм авто-истечения (фоновые задачи / TTL в БД / cron + проверка по end_time).
- **Смена даты/времени бронирования:** есть баг с выбором ПК при редактировании брони — требуется нормализация идентификаторов и серверная валидация входных данных.
- **2FA и смена пароля:** кнопки есть, функционал не реализован (см. Roadmap).
- **Админка:** работает только список ПК + поиск.
- **Медиа в БД:** нет полей/данных для изображений карточек — планируется миграция.

## Roadmap
- [ ] **Бронирование:** авто-освобождение слотов (cron/TTL), запрет пересечений; изменение брони без «прыжка» к другому ПК
- [ ] **Миграции БД:** таблица pc_images или поле image_url, индексы по pc_id, (start_time, end_time)
- [ ] **Админ-панель:** CRUD по ПК, пользователям, бронированиям; базовые графики по загрузке
- [ ] **Профиль:** смена пароля; 2FA TOTP (например, через OTPAuth)
- [ ] **Тесты:** unit на утилиты времени/валидации; e2e (сценарий «бронирование → истечение → доступность»)
- [ ] **CI/CD:** GitHub Actions (lint/test/build), превью-деплой фронта; отдельный деплой API
- [ ] **Медиа:** хранение картинок (S3/Cloudinary) + lazy-loading
- [ ] **Документация:** docs/API.md (контракты), ER-схема docs/db.png
- [ ] **Перфоманс:** code-splitting, prefetch данных карточки, кэширование на API

## Цель проекта
Показать умение вести фичи end-to-end на клиент-серверной архитектуре:
интерфейс → бронирование времени → валидация и хранение в БД → роли/админка → метрики и деплой.
